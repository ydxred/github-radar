# 开源雷达 · GitHub Radar

![开源雷达：打开新标签页，遇见值得探索的开源项目](store-assets/promo-1400x560.png)

把 GitHub 热门项目、收藏和阅读笔记放进新标签页。给好奇心留一扇窗，也给发现过的好项目留一个位置。

**基础扩展独立运行，无需账号、API 密钥或本机服务。** 它直接读取 GitHub 公开榜单，将个人资料保存在当前浏览器。需要桌面入口或中文 AI 解读时，也可以运行仓库提供的本机 Web 服务。

> Chrome 应用商店尚未确认公开发布。目前可从 GitHub Releases 下载安装包或自行构建源码，手动加载扩展；GitHub 发布包不代表已经通过商店审核。

## 可以做什么

- **发现热门项目**：查看日榜、周榜、月榜，按编程语言筛选。每份榜单显示来源和更新时间；有可用缓存时，网络失败会保留旧数据并提示状态。
- **按领域慢慢逛**：汇总已收录项目中的 AI 与智能体、开发工具、数据分析、金融量化、学习资源等内容。分类由项目名称和简介推断，可以重叠，也可能遗漏。
- **建立自己的项目清单**：收藏、记录笔记、标为已读、隐藏暂时不感兴趣的项目，再从最近浏览中找回来。收藏是本地清单，不会操作 GitHub 账号的 Star。
- **看真实变化**：保留采集时观察到的榜单快照，查看收藏项目的公开版本动态。“新发现”表示本资料库首次收录，不代表项目刚刚创建。
- **整理与备份**：搜索当前列表中的项目和笔记，导入、导出个人资料 JSON，或从内置备份恢复。
- **按需中文解读**：可选连接自己的 Codex，阅读项目用途、适用人群、开始方式、使用门槛和注意事项。本机 Web 还提供手动选择的 Qwen 本地推理方式。

搜索作用于当前列表或本地收录库，不是 GitHub 全站搜索。历史曲线只使用实际采集到的记录，不补造过去的数据；日、周、月榜的新增 Star 也不直接混为同一个比较口径。

## 选择适合你的使用方式

| | 独立 Chrome 扩展 | 本机 Web 服务 |
| --- | --- | --- |
| 打开方式 | 新建一个普通标签页 | 浏览器访问本机地址；Ubuntu 可安装桌面入口 |
| 日常使用依赖 | Chrome 120 或更新版本、可访问 GitHub 的网络 | Node.js 24 或更新版本、运行中的服务 |
| 个人资料存放 | 当前浏览器的 IndexedDB | 本机 `data/radar.sqlite` |
| 自动采集 | 至少一个雷达标签页打开时运行 | 服务运行且电脑未休眠时运行 |
| 中文解读 | 可选连接本机配套服务，使用自己的 Codex | 可选 Codex 或 Qwen 本地模型 |
| 账号与密钥 | 基础功能不需要；不保存 GitHub Token | 基础功能不需要；可选配置 GitHub Token |

两种方式的资料库**分别保存，不自动同步**。可以通过导出、导入资料 JSON 搬移收藏和笔记。

## 安装独立扩展

**直接使用，无需安装 Node.js：** 从 [最新发布页](https://github.com/ydxred/github-radar/releases/latest) 下载 `开源雷达-独立本地安装-2.0.0.zip`，解压后，在 `chrome://extensions/` 开启开发者模式，点击“加载已解压的扩展程序”，选择包含 `manifest.json` 的文件夹，再打开一个普通新标签页。安装完成后请保留解压目录。

从源码构建需要 **Node.js 24 或更新版本**及 npm；使用扩展时不需要继续运行 Node.js。

```bash
git clone https://github.com/ydxred/github-radar.git
cd github-radar
npm ci
npm run build:extension
```

1. 在 Chrome 地址栏打开 `chrome://extensions/`。
2. 开启“开发者模式”，点击“加载已解压的扩展程序”。
3. 选择刚刚生成的 **`browser-extension/`** 文件夹。该文件夹直接包含 `manifest.json`，不要选择仓库根目录或 `extension/` 源码目录。
4. 新开一个普通标签页。如果 Chrome 询问是否保留新标签页更改，选择保留开源雷达。

请保留加载的文件夹，Chrome 后续仍会从这里读取扩展文件。若已有其他新标签页扩展，需要在 Chrome 中选择启用哪一个。无痕窗口不使用这个新标签页入口。

更新源码后，先在设置中导出个人资料，再重新执行 `npm ci`、`npm run build:extension`，最后在 Chrome 扩展卡片上点击“重新加载”。

更多安装与资料迁移说明见 [浏览器扩展安装指南](docs/浏览器扩展安装.md)。

## 第一次打开后

页面会先加载当前榜单，再逐步补充领域发现。默认关注总榜及 Python、TypeScript、JavaScript、Go、Rust、Java、C++ 的日榜和周榜，共 16 个榜单，每两小时检查一次；可在设置中调整范围、间隔或暂停采集。

扩展的采集随标签页运行。关闭全部雷达标签页、退出浏览器或电脑休眠后会暂停；浏览器冻结标签页也可能推迟执行。再次打开后继续采集，不会补齐错过的所有时刻。

GitHub 匿名 API 有额度限制。榜单页面与项目详情使用不同的请求路径，详情或收藏动态可能暂时受限；设置中可查看连接与额度状态。收藏动态每轮最多检查 10 个项目，版本列表只展示接口返回范围内的近期稳定版本，并不代表完整发布历史。

收藏和笔记会保存在当前浏览器。**建议第一次整理完资料后就导出一份 JSON，之后定期更新这份外部备份。**

## 可选：运行本机 Web

完成克隆和 `npm ci` 后，在项目根目录运行：

```bash
npm start
```

打开 **http://127.0.0.1:4317/**。服务只监听本机回环地址，默认不会开放到局域网或公网。终端关闭或进程停止后，网页和后台采集都会停止；已有本机数据仍保留在磁盘。

本机版本使用 Node.js 内置 SQLite，默认将资料保存在项目的 `data/` 目录。更换数据位置可以在启动前设置 `GITHUB_TOP_DATA`。独立扩展的可选 Codex 连接固定使用 `127.0.0.1:4317`，需要保留该端口。

### Ubuntu 桌面入口

仓库提供适用于 Ubuntu 桌面与 `systemd --user` 的安装脚本，需要 `curl`、Python 3 和常用 XDG 桌面工具：

```bash
bash scripts/install-desktop.sh
bash scripts/open-web.sh --check
```

脚本会创建用户服务及“开源雷达 Web”桌面入口，并启用登录后的服务启动。日常点击桌面入口会先确保服务就绪，再打开网页；桌面环境如提示是否信任启动器，请确认允许启动。

查看或管理服务：

```bash
systemctl --user status github-top.service
systemctl --user restart github-top.service
systemctl --user disable --now github-top.service
```

安装后请保留项目目录。移动目录、切换 Node.js 安装位置后，应重新运行安装脚本。本机服务和桌面脚本主要在 Ubuntu 上验证。

## 可选：中文 AI 解读

基础榜单、收藏、笔记与备份都不依赖 AI。**打开页面不会自动生成解读；点击生成才会调用所选模型。** 结果会缓存，重复查看已有结果无需再次生成；手动重新生成会发起新的调用。

### 通过自己的 Codex 解读

1. 自行安装 Codex CLI，并使用自己的 ChatGPT 账号登录，确保账号有可用 Codex 额度。
2. 运行本机 Web 服务，在网页设置中启用 Codex 解读。这也是本机 Web 的默认解读方式。
3. 使用源码安装的扩展时，在扩展设置中点击“连接本机 Codex”，主动授予访问 `http://127.0.0.1:4317/*` 的可选权限。
4. 打开项目详情，点击“用 Codex 解读”生成内容。

扩展只向本机服务传入公开项目标识及生成选项；服务读取公开 README，再通过本机 Codex CLI 请求 OpenAI 云端模型。**这会使用你自己的 Codex 额度，不是离线推理，也不需要额外填写 API Key。** 当前接入仅接受 ChatGPT 登录状态，不支持 API Key 登录模式。

用于解读的项目内容来自公开 README，私人笔记、收藏列表和 GitHub Token 不作为解读输入。程序在只读环境中约束 CLI 进行资料解读，不执行 README 中的安装命令。每次最多读取 README 前 24,000 个字符；发生截断时，结果会注明资料为节选。解读可能有遗漏，应结合原项目文档判断。

扩展中“断开并撤销权限”会停止其访问本机服务，不会删除服务端已有缓存。配套服务按本地构建清单校验扩展来源；以上步骤适用于仓库源码安装版，未来商店版可能使用不同扩展标识，需要另行适配准确来源。

Codex 的登录与非交互运行方式可参考官方的 [身份验证说明](https://learn.chatgpt.com/docs/auth) 和 [非交互模式说明](https://learn.chatgpt.com/docs/non-interactive-mode)。

### 只在本机推理：Qwen

本机 Web 提供手动选择的 Qwen 模式，独立扩展目前不连接该模式。安装脚本使用固定版本及 SHA256 校验下载官方模型和运行时，当前适用于 Ubuntu / Linux x86_64：

```bash
python3 scripts/install-local-model.py
```

安装完成后，在本机 Web 设置中选择“本机离线模型”。下载和首次获取项目 README 需要联网；模型推理在本机完成。

| 参数 | 当前实现 |
| --- | --- |
| 模型 | Qwen3-1.7B-Q8_0，模型文件约 1.83 GB |
| 运行时 | llama.cpp b11207，CPU 推理，6 线程 |
| 模型目录 | `~/.local/share/github-top/local-ai`，可用 `GITHUB_TOP_AI_HOME` 修改 |
| 运行方式 | 首次生成时启动，空闲 5 分钟后退出 |
| 阅读范围 | 清理 HTML 后的 README 前 6,000 个字符 |

需要为模型及运行时预留磁盘空间和数 GB 可用内存。生成速度取决于电脑性能。**Qwen 失败时不会自动切到 Codex 消耗额度，Codex 失败时也不会擅自切换模型。**

## 数据与隐私

扩展不接入广告或统计分析 SDK，不读取其他标签页、浏览器全局历史、Cookie、密码或 Codex 登录凭证。其“最近浏览”仅记录在雷达内打开过的项目。网络请求包括 GitHub 公开榜单与 API、作者头像，以及主动启用后的本机 Codex 服务；这些外部服务会收到正常网络连接信息。

- **扩展个人资料**：收藏、笔记、阅读标记、最近浏览和显示偏好保存在当前浏览器；最近浏览最多 100 项，个人资料总量按导出 JSON 的 UTF-8 大小限制为 8 MiB，单条笔记最多 3,000 字符。
- **扩展内置备份**：自动、手动及恢复前备份合计最多保留 14 份。备份覆盖个人资料，不包含收录库、公开缓存、采集设置或本机连接授权。卸载扩展或清除浏览器数据，可能同时删除主资料和这些备份。
- **本机 Web 数据**：收藏、笔记、快照等保存在 `data/radar.sqlite`；SQLite 备份在 `data/backups/`。设置、可选 GitHub Token 和模型缓存分开保存，不在资料 JSON 内。
- **资料迁移**：导入采用合并方式，保留已有的非空笔记。JSON 导出适合迁移个人资料，不是整个运行环境或全部采集历史的镜像。

公开隐私说明见 [开源雷达隐私政策](https://github-radar-ydxred.yangxxq.chatgpt.site/privacy.html)，扩展内也附有可离线打开的隐私页面。

## 构建、检查与打包

安装依赖后，先构建扩展，再执行检查与测试：

```bash
npm run build:extension
npm run check
npm test
```

测试覆盖榜单解析、错误与额度处理、资料导入导出、备份恢复、跨标签页协调、界面状态和可选 AI 接口等逻辑。自动测试不替代真实 Chrome 扩展安装验收，也不表示通过商店审核。

需要分发 ZIP 时，安装 Python 3 后运行：

```bash
npm run package:extension
```

该命令会先重新构建，再生成：

- `dist/开源雷达-独立本地安装-2.0.0.zip`：解压后通过“加载已解压的扩展程序”安装，保留固定开发版标识。
- `dist/开源雷达-商店上传-2.0.0.zip`：面向 Chrome Web Store 的上传包，移除开发版公开 key，由商店分配扩展标识。

`manifest.json` 中的开发版 key 是维持扩展标识的公开信息，不是登录密钥。不同扩展标识的数据空间彼此独立，切换安装渠道前请先导出资料。

### 项目结构

```text
extension/       独立扩展的数据、GitHub 请求、可选本机连接及清单
public/          扩展与本机 Web 共用的界面
server/          可选本机 Web、SQLite、采集与中文解读服务
scripts/         构建、打包、桌面入口与本地模型安装工具
tests/           回归测试和测试样例
docs/            使用说明
store-assets/    公开品牌图与页面截图
```

`browser-extension/` 和 `dist/` 是构建产物；`data/`、本机部署记录、模型文件和凭证不应提交到仓库。

## 常见问题

**不开账号，影响收集吗？** 公开 Trending 榜单可以直接查看。匿名 GitHub API 的额度会影响详情与收藏动态的刷新频率，遇到限制时会提示并等待恢复。本机 Web 可选配置 GitHub Token；独立扩展不要求或保存 Token。

**刚安装时领域列表很少？** 本地收录库需要先采集。保持一个雷达标签页打开，等待各个榜单逐步完成；也可在设置中手动采集。领域分类覆盖的是已收录内容。

**断网以后还能看吗？** 已保存的个人资料和可用缓存仍可查看；获取新榜单、新详情和 Codex 云端解读需要网络。

**本机 Web 打不开？** 先确认使用 Node.js 24 或更新版本，并在项目根目录运行 `npm start`。如果提示 4317 端口占用，检查是否已启动另一份服务。通过桌面入口安装的用户，可查看 `systemctl --user status github-top.service` 的错误提示。

**扩展连接不上 Codex？** 先确认本机 Web 能打开、设置中已启用 Codex、CLI 已使用 ChatGPT 登录，并保持服务运行。连接使用仓库构建出的扩展标识及默认 4317 端口；重新构建扩展后，必要时重启本机服务。
