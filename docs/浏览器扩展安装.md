# 开源雷达 · 独立新标签页 2.0.0

此版本无需安装 Node、本机服务、AI 模型，也无需账号或密钥。安装后在普通新标签页读取 GitHub 公开榜单，收藏和笔记保存在当前浏览器。首次联网采集会逐步填充领域发现。

## 当前安装方式

Chrome 应用商店尚未确认公开发布。可以从本仓库的 [Releases](https://github.com/ydxred/github-radar/releases) 下载独立安装包，或自行构建源码。

从安装包使用：

1. 下载 `开源雷达-独立本地安装-2.0.0.zip`，解压到打算长期保留的文件夹；确保该文件夹直接包含 `manifest.json`。
2. 在 Chrome 地址栏输入 `chrome://extensions/`。
3. 打开“开发者模式”，点击“加载已解压的扩展程序”，选择刚才解压的文件夹。
4. 新开一个普通标签页；Chrome 若询问是否保留新标签页更改，选择保留开源雷达。
5. 更新时先导出个人资料，再替换解压目录中的文件，在扩展卡片点击重新加载。

下载的独立安装包不需要 Node.js 或 Python。Chrome 会持续从该目录加载文件，请不要在安装后删除目录。独立扩展与本机 Web 版的资料库分别保存，不会自动互相同步。

从源码构建（需要 Node.js 24 或更新版本）：

```bash
git clone https://github.com/ydxred/github-radar.git
cd github-radar
npm ci
npm run build:extension
```

然后在 Chrome 的“加载已解压的扩展程序”中选择项目内生成的 `browser-extension/` 文件夹。[Chrome 官方加载说明](https://developer.chrome.com/docs/extensions/get-started/tutorial/hello-world)

## 数据、采集与日常使用

- 榜单直接从 GitHub Trending 获取，详情和收藏动态使用匿名 GitHub API。网络或额度问题会显示原因，有可用缓存时保留旧数据并标明时间。
- 默认关注日榜、周榜的 8 个语言范围（含总榜），共 16 个榜单；新标签页打开后逐步采集。分类依据真实收录的名称和简介推断，一个项目可能有多个分类。
- 自动采集只在至少一个雷达标签页打开时运行；关闭全部雷达标签页、退出浏览器、休眠期间暂停。浏览器节能或冻结标签页可能推迟执行，不承诺准点或补齐错过的历史。
- 收藏、笔记、阅读标记、最近浏览和主题设置保存在此浏览器，不向开发者上传，不会自动同步到其他电脑。多个标签页通过数据库事务协调写入。
- **个人资料总量上限为 8 MB**，按实际导出 JSON 的 UTF-8 大小计算（包括为兼容旧版保留的收藏备注字段），不包含 GitHub 公开榜单、详情等缓存。收藏、笔记或导入合并后超限，会拒绝本次保存并显示大小及原因，已有资料保持不变；可先导出，再减少不需要的记录。单个导入文件同样不能超过 8 MB。
- 每日首次使用保留一份个人资料备份，最多 14 份；备份只含收藏、笔记、历史、偏好、已读和隐藏标记，不包含收录库、榜单缓存或本机授权。
- **卸载扩展、删除浏览器配置或清除扩展数据可能同时删除资料与内置备份。请定期在设置中“导出资料 JSON”，保存到自己的文件夹。**
- Chrome 无痕窗口不支持扩展替换新标签页。正常新标签页默认仍聚焦地址栏；页面获得焦点后可用 `/` 搜索。[官方新标签页说明](https://developer.chrome.com/docs/extensions/develop/ui/override-chrome-pages)

## 搬入原桌面版收藏和笔记

1. 打开原桌面 Web 看板，在“设置与本机数据”导出资料 JSON。
2. 在独立扩展的“设置与浏览器资料”中选择“导入资料 JSON”。
3. 导入采用合并方式，同一项目已有的非空笔记优先保留，不覆盖为另一份内容。

旧版压缩包和服务端资料没有被放入商店包。商店首次安装可能具有与开发加载不同的扩展标识；切换到商店版前请先导出，再在商店版导入。

## 可选：继续使用自己的本机 Codex

这部分需要额外的本机配套服务，基础功能完全不依赖它。

1. 按上面的步骤克隆项目、安装依赖并构建扩展，然后运行 `npm start` 启动本机服务。打开 `http://127.0.0.1:4317/`，在设置中启用 Codex；Codex CLI 需自行安装并登录，账号需有可用额度。
2. 在独立扩展设置中点击“连接本机 Codex（可选）”，允许访问本机地址。
3. 扩展只检查服务身份与 Codex 登录状态，不生成内容。
4. 打开项目详情，点击“用 Codex 解读”才开始生成。服务读取公开 README 节选，发给 OpenAI 并使用你的 Codex 额度。私人笔记不发送。
5. “断开并撤销权限”会禁止扩展继续连接本机服务。已有服务端缓存不会因此删除。

本仓库包含配套服务源码，主要在 Ubuntu 上验证；基础扩展不依赖此服务。配套服务按本地构建清单的公开 key 推导并校验扩展来源，仓库安装包与源码构建使用同一开发标识。其他发布渠道（包括未来商店版）可能具有不同标识，需要单独配置准确来源；不能通过关闭校验或改成通配符解决。更完整的本机 Web 版启动说明见 [README](../README.md)。

## 构建与分发

- `npm run build:extension`：生成 `browser-extension/`，保留开发版固定公开 key。该 key 用于维持扩展标识，不是密码或私钥。
- `npm run package:extension`：还需要 Python 3，生成根目录含 `manifest.json` 的两个包：`dist/开源雷达-独立本地安装-2.0.0.zip`、`dist/开源雷达-商店上传-2.0.0.zip`。商店包去掉开发版 key，使用商店分配的标识。
- `npm run check` 和 `npm test`：构建后运行语法检查与回归测试。
- 隐私页面源码在 `extension/privacy.html`，宣传素材在 `store-assets/`。数据库、私人资料和本机发布记录不随仓库分发。
- GitHub 发布包可供手动安装，不代表已经通过 Chrome 应用商店审核。
